# 微服务：面试要理解的代价和故障

微服务复习重点是服务边界与跨服务可靠性。能部署多个 Spring Boot 应用，不代表系统问题已经解决。

## 为什么拆、何时不拆

拆分可能帮助团队独立开发、部署和扩容；同时增加网络失败、分布式数据一致性、调用链观察和运维成本。回答“是否要拆”时先看业务边界、团队协作和变化频率，再讲拆分收益与代价。小项目无需为了简历硬拆成很多服务。

## 一次同步调用要想清的事

`服务 A → 服务 B`，A 等 B 返回。需要回答：连接超时/读超时设多少、B 慢时线程是否被占满、B 返回 5xx 时是否重试、A 如何给调用方反馈、日志/trace 怎样定位。Spring Cloud OpenFeign 文档分别说明连接和读取超时的配置。[Spring Cloud OpenFeign 文档](https://docs.spring.io/spring-cloud-openfeign/reference/spring-cloud-openfeign.html)

**重试的核心问题**：A 超时，不代表 B 没做成功。查询可重试性通常较好；新增单据、支付、提交审批等写操作必须先有幂等键、去重/状态查询等约束，不能看到异常就重发。结合 [[01-Citic项目表达与证据]]：资金计划“生成成功、提交或响应失败”的实例，适合说明为何要核对业务结果。

## 四个常见组件，先理解职责

| 能力 | 面试要能解释 |
|---|---|
| 注册发现 | 服务地址变化时调用方如何找到目标；并非解决业务失败 |
| 网关 | 统一入口、路由、认证、限流；不等于所有安全问题都解决 |
| 配置管理 | 配置集中与动态更新；说明版本和回滚边界 |
| 熔断/隔离 | 下游持续失败时减少无效请求、保护调用方资源；还需监控和恢复策略。[Spring Cloud CircuitBreaker 文档](https://docs.spring.io/spring-cloud-circuitbreaker/reference/spring-cloud-circuitbreaker-resilience4j.html) |

## 跨服务数据一致性

本地数据库事务只覆盖本地资源。A 写库后向 B 发送消息：写库成功而发消息失败怎么办？可学习“业务写入与 outbox 记录同事务提交，后台转发并处理重复发送”的思路，但这也需要消费者幂等和失败重试，不会自动获得全局 exactly once。[Transactional Outbox 模式](https://microservices.io/patterns/data/transactional-outbox)

## 自测

- 下游接口超时，但对方可能已经创建单据，此时直接重试的风险是什么？
- 限流、熔断、超时、重试各解决哪一段问题？它们可能怎样互相放大问题？
- 两个服务共用一张数据库表，这样拆分的主要代价是什么？

最小练习：画一个订单服务调用库存服务的时序图，标出请求超时、重试、库存已扣减、响应丢失四个位置；写出每种情况如何识别与恢复。

## 先把“失败”分成三种

远端新增有三类可观察结果：明确返回成功；明确返回业务拒绝；调用超时或连接断开，**结果未知**。第三类不能直接改写为“新增失败”。若远端按稳定 `requestId` 可查询状态，先查；查到已创建就返回已有结果，查到处理中就等待或提示稍后核对。查不到也可能是记录尚未可见，所以在没有远端幂等契约和安全重试证明前，不能自动再次新增。调用方自己的去重记录也需要原子写入，进程内 `Map` 无法解决多实例与重启问题。

| 观察 | 对外说明 | 后续动作 |
|---|---|---|
| 远端明确成功 | 已创建 | 记录远端 ID 与业务键 |
| 远端明确拒绝 | 未创建，原因已知 | 按业务错误处理，修正后是否重发取决于契约 |
| 超时/断连 | 结果未知 | 按稳定业务键查远端，保留待核对状态 |
| 查询仍无记录 | 仍需判断可见性窗口 | 不把“暂时查不到”自动等同于“安全重试” |

### 动手题：结果不明的新增

入口：`C:\Projects\leetcode-top100\src\main\java\io\github\plaguewzk\leetplague\interview\distributed\RemoteCreateExercise.java`。先用假 `Gateway` 返回三类结果，**无第三方依赖**。实现 `createOnce` 与 `reconcile`：超时返回 `UNKNOWN`，`reconcile` 只查询、不调用 `create`。设计假网关计数，验证一次超时后两个方法累计只调用一次 `create`。模拟“远端已创建但响应丢失”和“查询时仍处理中”。扩展为多实例持久化去重时可用 MySQL，Java 接入自行配置 `com.mysql:mysql-connector-j`；不要把内存模型说成生产幂等保证。
